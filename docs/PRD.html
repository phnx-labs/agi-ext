What this is

AGI EXT is the VS Code and VSCodium extension for agents-cli. It turns an open-source editor into an integrated agents environment: every coding agent (Claude Code, Codex, OpenCode, Cursor, Antigravity, Grok, Kimi, Droid) runs as a full editor tab, the Active Session sidebar shows what the focused agent is doing, and the Project panel lists every session of the open project on every machine you own, the ones that need you pinned first, beside the project's pull requests and tickets. The editor becomes the place you steer a fleet from, the way it used to be the place you typed code.

The extension is a presentation layer. agents-cli owns every fact (sessions, devices, accounts, attention, activity) and every mechanism (launch, placement, resume, fork, stop, scheduling, watchdog). The extension renders what the CLI streams and turns a gesture into exactly one CLI verb. That split is the product's one architecture rule and the source of almost every requirement below.

It is for developers who already run several agents at once, usually across more than one machine, and who want to see and steer that work without leaving the editor. It is a private repository shipped publicly on the Marketplace and Open VSX under the frozen identity swarmify.swarm-ext.

Summary

Open the editor, press one chord, and an agent starts on the right machine with the right account, in the folder you have open. Look at the sidebar and know what it asked, what it did, and what is left. Open the Project panel and see every agent on the project wherever it runs, reach the ones waiting on you, and start an agent on the next ticket. Close the laptop, come back, and the tabs are exactly where you left them. None of that starts a poller, parses a transcript, or invents a status.

Goals

An agent starts from the editor without a prompt. Agents: New <Harness> opens a tab and the agent is running on a fleet worker with a balanced account in the open workspace. Check: press Cmd+Shift+A on a workspace, watch the tab open with agents run <harness> --interactive --device auto --cwd <workspace> --strategy balanced --mode auto and a live prompt inside it, with no picker shown.

The editor never invents a status. Every phase, needs-you flag, label, and timeline step shown comes from a row the CLI streamed. Check: with the stream stopped, the sidebar says "Waiting for the session stream…" and names the command it expects instead of showing an empty card.

Seeing costs nothing. Selecting a Project panel card, switching tabs, and opening the sidebar spawn no process. Check: ps shows exactly one agents feed watch --json child for all windows while the Active Session sidebar or the Project panel's Sessions tab is visible, and none when neither is.

Tabs survive the editor. Reload, crash, or quit and the agent tabs come back bound to their live sessions. Check: reload the window with three agent tabs open; three tabs return with their labels, and none of the sessions were stopped.

Every session of a project is one list. The Project panel's Sessions tab shows local, remote, background, and ended sessions with the same card shape and the same needs-you rule. Check: a session of this project started on a worker box by another machine appears in the panel with its machine on the card, and focus (↗) opens it in the window that owns the project.

A person sees what is asked from where they are. A permission, question, or plan review pins its session to Your move (asks) in the Project panel with the agent's own question, and the Active Session sidebar shows the same ask under its header with Reply and Focus. Check: trigger a permission prompt in a tab; the session joins Your move with the harness's question, and it leaves only when the CLI removes the attention row.

Non-goals

No scheduler in the extension. Nothing in the extension launches, resumes, kills, injects, or rotates anything on a timer. The CLI daemon is the only scheduler. A second scheduler in a UI process caused the resume storms and the 31 percent idle CPU incident the current design exists to end.

No transcript parsing or local state reads for facts. The extension does not read ~/.claude/projects, terminal registries, or session state files to decide anything the stream can carry. Remaining readers (src/monitor/sessionParse.ts, src/monitor/readinessDetector.ts) are recorded debt, scheduled for deletion, never extended.

No second platform. The extension does not score devices or accounts, resolve project paths, decide fork identity, or reproduce resume compatibility. Each of those has one owner in the CLI and the extension calls it.

No second session preview. The Project panel is a list whose cards select; the Active Session sidebar is the one session preview. The deleted Fleet dashboard's persisted detail-rail preference produced a blank third-width column on open, and two previews of one session drifted.

No Gemini integration. The extension has no Gemini launch definition, installer, watchdog registration, prewarm configuration, transcript parser, or context-file alias target. Opening a workspace never creates GEMINI.md, even when an old explicit alias mapping requests it. Existing files remain untouched. Other configured aliases still work. The CLI catalog snapshot retains legacy ids solely to match the CLI protocol, not to install or offer the retired harness.

No local-first execution path or silent fallback. A launch under the default target goes to the fleet worker pool. A missing CLI noun is an upgrade error, never a filesystem fallback.

No API keys held by the extension. Autogit generates commit messages through agents run claude --model haiku. The Foreman voice orb and its agents.openaiApiKey setting were deleted with the Fleet dashboard in 0.9.394.

Findings

Three observations from running the extension shaped these requirements more than any design preference.

An always-on session watcher was removed in August 2026 because it pinned about 31 percent of a CPU core and leaked ssh fan-out to feed a view nobody had open. Restoring it behind a demand gate, so the single producer exists only while a visible sidebar or Project Sessions tab, an open Resume picker, or an unresolved tab needs it, is what made the stream affordable again. The same month a side-channel fetch per row produced the CPU incident recorded as agi-cli#3019; that is why a missing field goes onto the CLI row and never into a client fetch.

A persisted "detail rail open" preference in the Fleet dashboard (deleted in 0.9.394) restored a blank third-width column on open with nothing selected, and two previews of one session (the rail and the sidebar) drifted from each other. Removing the rail and making the sidebar the one preview removed the whole class of defect.

Ordinary launches once resolved the workspace through agents projects view <cwd>, and the first weak match in a monorepo silently sent the terminal to a child project's default path. Emitting the exact open workspace as --cwd and reserving --project for the explicit Pick Project command fixed it, and a recovery mapping that was machine-global instead of per-workspace produced a multi-window resume storm on reload. Both are now invariants enforced in code and tests.

Start an agent in a tab

You are in a workspace and want an agent working on it now, without deciding where it runs or which account it uses.

You press Cmd+Shift+A, or pick Agents: New Claude (or any presented harness) from the palette. The extension reads the one setting that matters, agents.launch.defaultTarget, and builds one command. Under the default auto that command is agents run claude --interactive --device auto --cwd <workspace> --strategy balanced --mode auto (the tests in src/core/launchTarget.test.ts assert the same string without the workspace). The workspace is passed exactly as opened: a monorepo root stays the root and a nested project folder stays that folder, locally and remotely. A tab opens named CL and the CLI places the run on a device from the worker pool, rotating the account by usage headroom.

When you want to choose one axis and let the CLI balance the other, the harness has five explicit variants. (Local) emits --local --cwd <workspace> --strategy balanced --mode auto, pinning the launch to the editor’s machine regardless of the configured target. Local defaults and Pick Host’s This Machine choice also emit --local. A hostless version pin emits --local and omits --strategy; an explicit host still wins. (Pick Host) prompts for the device and emits --device <name> --cwd <workspace> --strategy balanced --mode auto. (Pick Account) emits claude@ --interactive --device auto --cwd <workspace> --mode auto, with no --strategy, so the CLI routes to a picker-eligible worker and shows that device's account picker in the tab; a signed-out account can be chosen and authenticates in place. (Auto) chooses both without a prompt, ignoring the configured target, and emits the same --device auto --cwd <workspace> --strategy balanced --mode auto as the default. (Pick Project) is the only variant that replaces the workspace: it shows a project quickpick and emits --device auto --project <slug> --strategy balanced --mode auto, and the CLI resolves the project's configured path on the chosen worker. --strategy balanced rides every automatic-placement variant; only the account picker and a pinned version drop it.

What should happen: within a second a terminal tab exists, the status bar shows the agent's label and, when it runs elsewhere, the executing host shortened to its unique suffix. The tab title, the session's card and the status bar show one name: the CLI's resolved title, else its label (your /rename), else the topic or request (streamTitle, src/core/projectPanel.ts); the extension generates no name of its own and no longer reports a tab's title back to the CLI. When the CLI says what a session was started with (startedAs), its card shows it on a faint "started: …" line. Agents: Rename Session (Cmd+Shift+L) renames the session itself: it types Claude's /rename <name> into the tab, and the new name comes back through the stream; other harnesses have no rename the CLI reads, and the command says so. The picker and --strategy never appear together; --project and --cwd never appear together. These exclusions are enforced by buildAgentLaunchCommand in src/core/agents.ts.

Come back after a reload or a crash

You closed the editor, or it crashed, with agent tabs open. You want them back exactly as they were, and you want none of the agents killed by the reload itself.

You reopen the workspace. The extension reads the persisted tab metadata for that workspace (terminal id, harness prefix, session id, host, label, pinned version) and reopens each tab through the CLI's resume path. Each restored tab then rebinds from the live stream: the first row that claims the tab's terminal id on the same observer device and host is the tab's session.

What should happen: every tab returns with its label and icon; the status bar and sidebar follow the restored session once the stream reports it; the agent process was never signaled. Closing a tab by hand is different: only a real user close (TerminalExitReason.User) issues agents ps stop <id>. A reload is never treated as a close. Each window keeps its tabs in its own file, so a second window can neither resurrect a tab you closed nor erase this window's tabs; restore opens one tab per session, keeps each tab's device, and skips a session the window already shows.

Where this is still debt: src/core/prewarm.simple.ts still lists OpenCode sessions on tab open, slated for deletion once the CLI daemon owns restore.

See what an agent is doing

The active agent tab shows a copy icon and the first eight characters of its session ID. Hover exposes the full ID and remote host; clicking copies the full canonical ID. Switching to a text editor or a plain terminal clears the session tooltip. Remote attach titles omit host-only placeholders; execution host identity comes from structured stream facts, never task text.

You have several tabs and you want to know, for the one you are looking at, what you asked, what it has done, and whether it is stuck, without scrolling its terminal.

You focus an agent tab, or click a session card in the Project panel. The Active Session sidebar (the agentsPanel.terminal view) takes that session as its subject; the last of the two triggers wins. A focused tab whose harness has not reported its session id yet (Codex, Grok) is still the subject: the sidebar shows that tab, never the previously focused one, and renders its row once the stream binds the id or you set it with Set Session ID for Terminal. The sidebar renders synchronously from the warm presentation store as one card, top to bottom (owner review, 2026-10-12: fewer components, nothing important below the fold). The title line carries the harness icon, the session's title (your /rename, else the CLI's generated title) and three quick icons, each with its words in its tooltip: open its tab (↗; ▶ resume when no tab here holds it), fork (⑂: the panel's own tab forks in place, otherwise Agents: Fork (Pick Session)), and ⋯, a drawer inside the card with the model, the account label, the host, the short session id (copy, and a pencil to rebind the tab, offered even before the harness reports an id), chips for project, branch, a worktree badge only when the agent works in a linked worktree, the start time, tokens, and the raw identity lines; the drawer remembers whether it is open. Under the title one line states where the session is, by who has the ball (sessionStateOf, ballOf, the same words the Project panel uses): "Asks" (an open question or permission), "Stuck" (the CLI flags a live stall or failure), "Ready for review", "Idle" (it finished its turn and asked nothing), "Running", "Waiting" (its turn ended but its own background work still runs; a slowly breathing blue dot, and under the state a "Waiting on its own work" list names each subagent, background shell and monitor with how long it has run), or "Ended" (the process exited or is gone; it says nothing about whether the work succeeded), with how long it ran, when it last moved and, quiet at the end, the account it runs on. Asks and Stuck read amber. A Running session with no activity for five minutes shows "Running, but quiet since " with Open; the line is rendered with the row and revealed by a CSS animation delay, so the sidebar keeps no timer. Failed and policy-blocked tool calls stay behind one quiet line ("⚠ 6 failed · 12 blocked") that appears only when there are any and opens to the list. The goal follows as one line. When the agent's latest status post (agents feed post) says it is blocked and you have not written since, the state reads "Blocked" in red and a strip shows the agent's own title and words with Reply and Open tab. Then an open ask with its own words, how long it has waited, Reply and Focus. Request shows your avatar (fetched from Gravatar by a hash of your email) and name, your sentence (two lines), thumbnails of images you pasted (also when the agent runs on another machine), and the whole turn behind a fold. Made follows: one row of previews you scroll sideways. The session's PR leads, read at a glance: GitHub mark, #number, one status word (Ready, Checks running, Failing, Conflicts, Changes requested, Needs review, Checks passed, Draft, Merged, Closed; prVerdict, the word and color the Project panel card's PR chip shows too, so a PR with green checks and a conflict reads Conflicts on both), the title, and a bar with one segment per check and the count passed (6/6). A click opens the PR's GitHub page as an editor tab (see Open a PR or ticket as a tab); nothing unfolds under the row (owner video, 2026-10-12). Merging is in ⋯: the PR's review and merge glyphs, at most one action decided from the row (Merge when ready, Merge when green while checks run), confirmed in a dialog and run as one agents projects prs merge|automerge … --sha <head> pinned to the head commit shown, and Merge ▾, which reads that PR once and offers squash, rebase or a merge commit (--method) when GitHub would merge it, and an admin merge that bypasses branch protection (--admin) only when you are an admin of a repo that allows the bypass, run only after its own warning dialog and a second read confirming the head did not move (the same flow as a Project panel PR row); without a head commit it offers nothing and says why. The session's other PRs follow, then its ticket as a tile with its title and state when this window has read them (the Issues list or the ticket's detail; the row carries only the id, and the tile never reads Linear itself), which opens the ticket in the Project panel's Issues tab. Then every artifact file the CLI lists, newest first: an image as a downscaled preview (decoded once in the webview and cached), a page or document by its type mark, each with its name, type and age; a tile opens the file (a plan or report as an editor tab in the Agents Reader beside the agent that wrote it; for an agent on another machine the file is copied here first, the tile saying it is opening while it copies; a copy that fails says why in full, and a file from an agent worktree that was since removed names the worktree and where the merged copy is). A page, document or image on this machine carries Share on hover: it asks who can open the link (Rush org, Only me, Anyone with the link), runs artifacts share <file> --visibility <org|me|unlisted> --json once, copies the URL and offers Open; a refusal (a file with emails or credential-shaped strings) is shown as the CLI words it. Under Made, one Related line of chips names up to three other sessions to handle together with this one: the same ticket or PR first, then the same branch in the same folder, then a similar title or request (only the words that set a session apart count; words most sessions share are ignored). Each chip carries its state dot and, in its tooltip, why it is related; a click makes it the subject. It is a selector over the rows already in the presentation store (relatedSessions), so it starts no process. Last comes the activity strip and the feed it filters. The strip shows tool activity across the whole session, idle stretches collapsed into labeled gaps and markers for your messages, subagents and the open ask; clicking a bar jumps to that moment, and dragging across bars chooses any range (remembered per session; it lapses if it no longer lies inside the strip), shown as " selected ×". Bars outside the range dim, Made tiles changed outside it dim in place, and the feed lists only what falls in it. A stretch whose steps are older than the row's last few says so instead of looking empty. A turn the harness wrote for itself (a background task's <task-notification>, a <system-reminder>) is never shown as your message, as a step, or as the agent's current activity, and its marker leaves the strip so marker N and turn N stay the same turn. Chips switch the feed: All (newest three steps and the agent's status posts by time, the live line, failures and milestones; "N more" stays open across updates), Updates (the agent's agents feed post posts, from the stream's activity events, with their links; a blocked post reads red), You, Failed, or, one sessions <id> --include call per click, the agent's messages, tool calls or reasoning; and, when the row has them, Files (the changed files with the true total, as a tree in which a folder with a single child folder folds into one row, or as a flat list, marked with Source Control's A, M and D), Subagents (type, model, how long it ran and its tool count, running first, finished ones beyond the newest three folded, each opening to what it was asked, its verdict and a link to its transcript) and Checklist. With a range chosen on a local session, Show tool calls loads the calls once and draws them as a zoomed lane over the range. The reply field floats over the bottom of the panel, so it is in reach without scrolling. It is built once and never redrawn, so an update never takes its caret or what you typed, and a draft belongs to its session. Its mic dictates: click to talk, click again to stop, and the words land in the field to edit before Enter sends. It records the default microphone with ffmpeg and transcribes on this machine with whisper.cpp's whisper-cli and the agents.dictation.model model; nothing leaves the machine, and a missing tool, model or microphone permission is said in the field. A stream update patches the card in place rather than rebuilding it (patchChildren), so nothing jumps, hover stays, and a scrolled strip or an open fold stays as you left it (owner video, 2026-10-12). ‹ › at the top go back and forward through the sessions the sidebar showed (a Project panel card, a Related chip or a tab switch each leave a stop) and name where Back leads. The status bar shows the active tab's label and, for a remote session, its host.

What should happen: switching tabs paints instantly with no await, fetch, or lazy enrichment. On an older CLI the cards degrade honestly: request falls back to the cleaned prompt and then the topic, timeline falls back to checkpoints, and the Files card does not appear. Two states are never faked: when no reset has been seen for the subject's scope the Timeline says "Waiting for the session stream…" and names the command; when the CLI reports the timeline unavailable it says so with the CLI's reason.

Manage a project from the left sidebar

You run several agents on one project and want the project's state in view while the right sidebar shows the session you are in: what is open, which sessions stopped, which PRs are ready, what is next.

Above its tabs, the Project panel shows two quiet lines from one linear goals --json read (the goals of the project's Linear workspace) (when the panel shows, at most once a minute, or on Refresh): ◎ the company goal with its target date (this week's cycle goal in its tooltip), then ☀ Today, your day goal, with its ticket id; each opens in Linear, and a failed read says so on one faint line. Sessions working on today's goal (its ticket id in the title, topic or latest reply) carry ☀ on their card, and the Sessions header offers "☀ N on today", a remembered toggle that shows only them. The Project panel is one sidebar view with four tabs: Sessions, Issues (the project's Linear tickets), Review (its pull requests) and, last, Settings (a gear); the cycle and goals already sit above them, so there is no Overview tab. The active tab shows its label (and, for Sessions, how many are live), a badge on the Sessions icon counts open asks (never an idle turn) as of the last time Sessions was shown (the stream runs only while Sessions is visible), arrow keys move between tabs, the panel remembers the active tab per workspace, and each tab keeps its scroll while the panel is open. Only the active tab loads. Its project is the one containing the open workspace folder (agents projects status --path <folder> --json), or the one you choose, remembered per workspace. A button above the goals names it and says whether it was found from the folder or picked; its menu (one agents projects list --json and one linear projects --json read when it opens) lists every live Linear project, each through the agents project that links it with its repositories (so Review works), or "tickets only, no repositories linked" when none does, then the agents projects whose Linear link is missing or gone ("Linear link gone (AGI UI)"); the shown project is checked and the one found from this folder says so. Detection can be wrong, so a pick wins and is remembered per workspace; Use detection again clears it. With nothing found the button reads "No project" and the menu is how you pick one. Switch Project offers the same rows. Sessions lists every session of the project from the session stream already in memory, filtered on the CLI's confirmedProject, so it starts no process; until agents-cli resolves a renamed project's old names, a session whose checkout is one of the project's repositories (the folder's root, or the repos agents projects list names) is listed too when the CLI gave it no project or a name no registered project has (a session of another live project in the same repository stays there), and its ⋯ menu says what the CLI filed it under; Agents: Resume Session… applies the same rule; the stream is demanded only while Sessions is the visible tab, and it redraws when the stream changes. It is built to be read at a glance (AGENTS.md, Design). The tab already counts live sessions and marks the ones that need you, so the header holds only its controls: a search icon (⌘K; see below) and a ⇅ menu with checkmarks: Sort (last active, newest, name), Show (tabs with no agent, ended) and Group (App, Machine, State, None); the choices, folded groups and hidden sessions are remembered per workspace. Ended sessions are shown by default in a folded Ended group (under App and State grouping), so a session to resume is one unfold away; preferences saved before this default get it too, unless they had turned Ended on or group by Machine or None, which have no Ended group and keep Ended off. Only a real ask is your move (owner recording, 2026-10-13: 11 of 12 Your move cards were idle). Pinned above every grouping, Needs you now holds the asks agents-cli marks urgent or high and Asks the normal and low ones (the attention item's urgency; a CLI that sends none reads normal), each ordered by urgency, then a session whose agent posted that it is blocked (its latest agents feed post is status.blocked and you have not written since; "Blocked"), then the longest wait, then the CLI's attention kind (question, permission, plan review, declared, failure, stall, review; ATTENTION_KIND_RANK, src/shared/sessionState.ts). A stall or failure the CLI flags is an ask too ("Stuck"). Below them, Ready for review (an open review request) and Idle · finished, no tab here (folded by default, with its count); both hold only sessions with no tab in this window. Every session with a tab in this window stays in Open tabs, working or finished, in tab order (whatever the sort), each card carrying the number of its tab ("⌘3" on macOS, "Alt+3" elsewhere), matched to its tab by terminal identity, not by label, so two tabs with one name keep two numbers; only an ask leaves it, for the pinned group where its answer buttons are, so the card exists once (PHNX-4387). Grouped by State, the rest fall under Running, Open tabs (finished) and Ended. Grouped by App, each group is where the session lives, with the app's icon: Open tabs (this window, with its workspace name, e.g. agents), each other editor window by the workspace its tab's window has open (observerTerminals[].workspaceDir from the CLI), Ghostty (the row's terminal app), other terminals, Background (a headless run, a team member or a cloud task), and Tabs with no agent (an ended session whose tab is still open here, with Close all). A group header carries a count and one dot per state, so a folded group still says what is inside. Each session is an outlined card that always shows the same thing, so nothing moves under the pointer (owner video, 2026-10-12): the harness's logo (from the row's agent type) before its title, and how long since it last moved; a pill with its state as a dot and a word (an Ended one adds how long it ran, "Ended · ran 13h 8m", and when, "yesterday 6:50 PM → today 7:56 AM") (named the same on every surface by sessionStateOf and ballOf, src/shared/sessionState.ts, by who has the ball: Asks, Stuck, Ready for review, Idle, Running, Running · no transcript, Waiting, Ended; a crashed or orphaned process is Ended, which says nothing about whether the work succeeded; the Running dot breathes, except under reduced motion). Waiting is a session with status idle whose own background work still runs (the row's pending: running subagents, background shells with no completion yet, active monitors): its blue dot breathes slowly, chips count each kind (⑂ subagents, ▸ shells, ◉ monitors) and their hover lists each with how long it has run, and it is the agent's ball, so it is never an ask. The meta line holds only the pill, the Waiting chips and, when the session's repository is not the one this window has open, that repository's name; the title carries ⚡ for fast mode and ◆ for high, xhigh or max effort when the row says so. The machine sits dimmed at the bottom right. Then a two-line preview: an ask in an amber box headed "Asks · <the question's header>", its question in two lines (the full text on hover, and a click on it opens it in place), its answers as one-line buttons "1 Yes, publish from zion" (each option's description on hover) from the attention item's choices, else its question's options, and two links, Other… (a reply box; Enter sends) and Try another way (it sends "I can't answer this right now. The title is the CLI's title, else the topic, your label or the request, skipping a note Claude Code inserts when another session writes in ("Another Claude session sent a message: …"), a sub-agent hand-back and a bare slash command (sessionTitle, src/core/projectPanel.ts). Hover only reveals the card's icons. A click on a card shows the session in the other sidebar, and when its tab is in this window brings that tab to the front; it never resumes or opens anything. Switching tabs moves the selection the other way, on either VS Code event (the active terminal or the active editor tab; the first alone misses editor-area terminal tabs): the card for the tab in front is selected, its group opens if it was folded, and it scrolls into view without a flash. A selected card has its own look, a gold rail inside its left edge, and the front tab's card is headed "This tab". ⌘K in the Agents views or, on macOS, an agent tab (Ctrl+K in the Agents views elsewhere, so the terminal keeps readline's Ctrl+K; Agents: Search Sessions) is VS Code's own picker with sections, in order: Artifacts (each artifact this machine knows, artifacts list --json, by the rendered page's real title, saying "made by on "), Sessions (every session this window knows, with its state dot), Tickets and Pull requests (what the panel already read), then, for a query of two or more words while the Lead is installed, "Ask the Lead: “”", which hands the words to agents.lead.ask. An artifact's session is the agents://session/<id> link in its rendered page, else the session whose written files (sessions artifacts <id> --json) include it, else the session working in the worktree it sits in.
