What this is

AGI EXT is the VS Code and VSCodium extension for agents-cli. It turns an open-source editor into an integrated agents environment: every coding agent (Claude Code, Codex, OpenCode, Cursor, Antigravity, Grok, Kimi, Droid) runs as a full editor tab, the Active Session sidebar shows what the focused agent is doing, and the Project panel lists every session of the open project on every machine you own, the ones that need you pinned first, beside the project's pull requests and tickets. The editor becomes the place you steer a fleet from, the way it used to be the place you typed code.

The extension is a presentation layer. agents-cli owns every fact (sessions, devices, accounts, attention, activity) and every mechanism (launch, placement, resume, fork, stop, scheduling, watchdog). The extension renders what the CLI streams and turns a gesture into exactly one CLI verb. That split is the product's one architecture rule and the source of almost every requirement below.

It is for developers who already run several agents at once, usually across more than one machine, and who want to see and steer that work without leaving the editor. It is a private repository shipped publicly on the Marketplace and Open VSX under the frozen identity swarmify.swarm-ext.

Summary

Open the editor, press one chord, and an agent starts on the right machine with the right account, in the folder you have open. Look at the sidebar and know what it asked, what it did, and what is left. Open the Project panel and see every agent on the project wherever it runs, reach the ones waiting on you, and start an agent on the next ticket. Close the laptop, come back, and the tabs are exactly where you left them. None of that starts a poller, parses a transcript, or invents a status.

Goals

An agent starts from the editor without a prompt. Agents: New <Harness> opens a tab and the agent is running on a fleet worker with a balanced account in the open workspace. Check: press Cmd+Shift+A on a workspace, watch the tab open with agents run <harness> --interactive --device auto --cwd <workspace> --strategy balanced --mode auto and a live prompt inside it, with no picker shown.

The editor never invents a status. Every phase, needs-you flag, label, and timeline step shown comes from a row the CLI streamed. Check: with the stream stopped, the sidebar says "Waiting for the session stream…" and names the command it expects instead of showing an empty card.

Seeing costs nothing. Selecting a Project panel card, switching tabs, and opening the sidebar spawn no process. Check: ps shows exactly one agents feed watch --json child for all windows while the Active Session sidebar or the Project panel's Sessions tab is visible, and none when neither is.

Tabs survive the editor. Reload, crash, or quit and the agent tabs come back bound to their live sessions. Check: reload the window with three agent tabs open; three tabs return with their labels, and none of the sessions were stopped.

Every session of a project is one list. The Project panel's Sessions tab shows local, remote, background, and ended sessions with the same card shape and the same needs-you rule. Check: a session of this project started on a worker box by another machine appears in the panel with its machine on the card, and focus (↗) opens it in the window that owns the project.

A person sees what is asked from where they are. A permission, question, or plan review pins its session to Needs you in the Project panel with the agent's own question, and the Active Session sidebar shows the same ask under its header with Reply and Focus. Check: trigger a permission prompt in a tab; the session joins Needs you with the harness's question, and it leaves only when the CLI removes the attention row.

Non-goals

No scheduler in the extension. Nothing in the extension launches, resumes, kills, injects, or rotates anything on a timer. The CLI daemon is the only scheduler. A second scheduler in a UI process caused the resume storms and the 31 percent idle CPU incident the current design exists to end.

No transcript parsing or local state reads for facts. The extension does not read ~/.claude/projects, terminal registries, or session state files to decide anything the stream can carry. Remaining readers (src/monitor/sessionParse.ts, the recursive fs.watch in src/vscode/terminalReadiness.ts, src/monitor/readinessDetector.ts) are recorded debt, scheduled for deletion, never extended.

No second platform. The extension does not score devices or accounts, resolve project paths, decide fork identity, or reproduce resume compatibility. Each of those has one owner in the CLI and the extension calls it.

No second session preview. The Project panel is a list whose cards select; the Active Session sidebar is the one session preview. The deleted Fleet dashboard's persisted detail-rail preference produced a blank third-width column on open, and two previews of one session drifted.

No Gemini integration. The extension has no Gemini launch definition, installer, watchdog registration, prewarm configuration, transcript parser, or context-file alias target. Opening a workspace never creates GEMINI.md, even when an old explicit alias mapping requests it. Existing files remain untouched. Other configured aliases still work. The CLI catalog snapshot retains legacy ids solely to match the CLI protocol, not to install or offer the retired harness.

No local-first execution path or silent fallback. A launch under the default target goes to the fleet worker pool. A missing CLI noun is an upgrade error, never a filesystem fallback.

No API keys held by the extension. Autogit generates commit messages through agents run claude --model haiku. The Foreman voice orb and its agents.openaiApiKey setting were deleted with the Fleet dashboard in 0.9.394.

Findings

Three observations from running the extension shaped these requirements more than any design preference.

An always-on session watcher was removed in August 2026 because it pinned about 31 percent of a CPU core and leaked ssh fan-out to feed a view nobody had open. Restoring it behind a demand gate, so the single producer exists only while a visible sidebar or Project Sessions tab, an open Resume picker, or an unresolved tab needs it, is what made the stream affordable again. The same month a side-channel fetch per row produced the CPU incident recorded as agi-cli#3019; that is why a missing field goes onto the CLI row and never into a client fetch.

A persisted "detail rail open" preference in the Fleet dashboard (deleted in 0.9.394) restored a blank third-width column on open with nothing selected, and two previews of one session (the rail and the sidebar) drifted from each other. Removing the rail and making the sidebar the one preview removed the whole class of defect.

Ordinary launches once resolved the workspace through agents projects view <cwd>, and the first weak match in a monorepo silently sent the terminal to a child project's default path. Emitting the exact open workspace as --cwd and reserving --project for the explicit Pick Project command fixed it, and a recovery mapping that was machine-global instead of per-workspace produced a multi-window resume storm on reload. Both are now invariants enforced in code and tests.

Start an agent in a tab

You are in a workspace and want an agent working on it now, without deciding where it runs or which account it uses.

You press Cmd+Shift+A, or pick Agents: New Claude (or any presented harness) from the palette. The extension reads the one setting that matters, agents.launch.defaultTarget, and builds one command. Under the default auto that command is agents run claude --interactive --device auto --cwd <workspace> --strategy balanced --mode auto (the tests in src/core/launchTarget.test.ts assert the same string without the workspace). The workspace is passed exactly as opened: a monorepo root stays the root and a nested project folder stays that folder, locally and remotely. A tab opens named CL and the CLI places the run on a device from the worker pool, rotating the account by usage headroom.

When you want to choose one axis and let the CLI balance the other, the harness has five explicit variants. (Local) emits --local --cwd <workspace> --strategy balanced --mode auto, pinning the launch to the editor’s machine regardless of the configured target. Local defaults and Pick Host’s This Machine choice also emit --local. A hostless version pin emits --local and omits --strategy; an explicit host still wins. (Pick Host) prompts for the device and emits --device <name> --cwd <workspace> --strategy balanced --mode auto. (Pick Account) emits claude@ --interactive --device auto --cwd <workspace> --mode auto, with no --strategy, so the CLI routes to a picker-eligible worker and shows that device's account picker in the tab; a signed-out account can be chosen and authenticates in place. (Auto) chooses both without a prompt, ignoring the configured target, and emits the same --device auto --cwd <workspace> --strategy balanced --mode auto as the default. (Pick Project) is the only variant that replaces the workspace: it shows a project quickpick and emits --device auto --project <slug> --strategy balanced --mode auto, and the CLI resolves the project's configured path on the chosen worker. --strategy balanced rides every automatic-placement variant; only the account picker and a pinned version drop it.

What should happen: within a second a terminal tab exists, the status bar shows the agent's label and, when it runs elsewhere, the executing host shortened to its unique suffix. The tab title takes the canonical session name once the stream reports it. The picker and --strategy never appear together; --project and --cwd never appear together. These exclusions are enforced by buildAgentLaunchCommand in src/core/agents.ts.

Come back after a reload or a crash

You closed the editor, or it crashed, with agent tabs open. You want them back exactly as they were, and you want none of the agents killed by the reload itself.

You reopen the workspace. The extension reads the persisted tab metadata for that workspace (terminal id, harness prefix, session id, host, label, pinned version) and reopens each tab through the CLI's resume path. Each restored tab then rebinds from the live stream: the first row that claims the tab's terminal id on the same observer device and host is the tab's session.

What should happen: every tab returns with its label and icon; the status bar and sidebar follow the restored session once the stream reports it; the agent process was never signaled. Closing a tab by hand is different: only a real user close (TerminalExitReason.User) issues agents sessions stop <id>. A reload is never treated as a close. Each window keeps its tabs in its own file, so a second window can neither resurrect a tab you closed nor erase this window's tabs; restore opens one tab per session, keeps each tab's device, and skips a session the window already shows.

Where this is still debt: src/core/prewarm.simple.ts still lists OpenCode sessions on tab open, slated for deletion once the CLI daemon owns restore.

See what an agent is doing

The active agent tab shows a copy icon and the first eight characters of its session ID. Hover exposes the full ID and remote host; clicking copies the full canonical ID. Switching to a text editor or a plain terminal clears the session tooltip. Remote attach titles omit host-only placeholders; execution host identity comes from structured stream facts, never task text.

You have several tabs and you want to know, for the one you are looking at, what you asked, what it has done, and whether it is stuck, without scrolling its terminal.

You focus an agent tab, or click a session card in the Project panel. The Active Session sidebar (the agentsPanel.terminal view) takes that session as its subject; the last of the two triggers wins. A focused tab whose harness has not reported its session id yet (Codex, Grok) is still the subject: the sidebar shows that tab, never the previously focused one, and renders its row once the stream binds the id or you set it with Set Session ID for Terminal. The sidebar renders synchronously from the warm presentation store, top to bottom. A compact header leads with the harness icon and the session's title (your /rename, else the CLI's generated title), then the running model, account and host. Its ⋯ menu opens a drawer inside the card with the short session id (copy, and a pencil to rebind the tab, offered even before the harness reports an id), chips for project, branch, a worktree badge only when the agent works in a linked worktree, the start time, tokens, and the raw identity lines; the drawer remembers whether it is open. Under the header one line states where the session is from the CLI row's phase: "Working 1d 2h · active 2 min ago", or "Needs you", "Your turn · ran 26h", "Ended", "Stopped", "Unknown", with when it last moved; the word is the same one the Project panel uses (sessionStateOf). When the harness has an open ask, a needs-you card sits under the header with its own words, how long it has waited, and Reply and Focus. Failed and policy-blocked tool calls stay behind one quiet line ("⚠ 6 failed · 12 blocked") that appears only when there are any and opens to the list. What the session produced comes next, before what was asked (PHNX-4289). Artifacts leads as a gallery: the newest image the session made fills the card width as a large preview, captioned with its title (the CLI's sidecar title, else the file name), its type and how long ago it changed; the other images follow as a two-up grid of tiles with a one-line caption, and files with no preview (pages, documents) close the card as compact tiles marked with a type glyph. Previews are downscaled once in the webview and cached; a tile opens the file (a plan or report as an editor tab in the Agents Reader beside the agent that wrote it; for an agent on another machine the file is copied here first, so it opens without a remote connection). The session's other PRs and its ticket sit under the gallery as links. Sort (latest edited first by default, oldest, name) and a Group by app toggle sit under the heading; grouped, the card shows the folders by app (Finder, GitHub, Linear), each a strip of thumbnails that its caret opens into a grid, with ↗ to reveal it in Finder. The heading folds the whole section to one line with the newest thumbnails, the apps involved and when the newest changed; these choices persist. The Pull request card follows when the session has a PR, read at a glance rather than in words: a ring for where it stands (spinning while checks run, closed with a check when ready, red when failing or conflicting, dashed for a draft), #number title, one status word (Ready, Checks running, Failing, Conflicts, Changes requested, Draft, Merged, Closed) and the session's branch. Under it one icon strip: a bar with one segment per check colored passed, running, failed or skipped with passed/total beside it, a review glyph (an outline when there is no review, green when approved, red when changes are requested) and a merge glyph (green when mergeable, red on conflicts); each icon carries its words in its tooltip and accessible label. Clicking the bar unfolds the checks by name, each with a link to its run. When the PR's checks turn green while you watch, the ring closes into a check once (not under reduced motion). The card offers Open on GitHub and at most one action decided from the row (Merge when ready, Merge when green while checks run), confirmed in a dialog and run as one agents projects prs merge|automerge … --sha <head> pinned to the head commit shown, never --admin; without a head commit on the row it offers no action and says why. Then the goal and the request. Request shows your avatar (fetched from Gravatar by a hash of your email) and name, your sentence, thumbnails of images you pasted (also when the agent runs on another machine), and the whole turn behind a fold. The Timeline opens with a seek bar of tool activity across the whole session, idle stretches collapsed into labeled gaps and markers for your messages, subagents and the open ask; clicking a bar jumps to that moment. When the session has more than one stretch of work, a chip per stretch (named by when it began) narrows the strip, the steps and the You and Failed lists to that stretch; bars outside it dim, and Clear range returns to the whole session. A stretch whose steps are older than the row's last few says so instead of looking empty. A turn the harness wrote for itself (a background task's <task-notification>, a <system-reminder>) is never shown as your message, as a step, or as the agent's current activity, and its marker leaves the strip so marker N and turn N stay the same turn. Filter chips swap the default summary (newest three steps, the live line, failures and milestones) for your messages, the failures, or, one agents sessions <id> --include call per click, the agent's messages, tool calls or reasoning. With a range chosen on a local session, Show tool calls loads the calls once and draws them as a zoomed lane over the range. Then the Checklist; the changed files with the true total, as a tree in which a folder with a single child folder folds into one row, or as a flat list (the choice persists), marked with Source Control's A, M and D; Subagents, each row showing its type (and model, when reported), how long it ran (or has been running) and its tool count before you open it, running ones first and finished ones beyond the newest three folded behind one line, opening to what it was asked (when reported), its verdict and a link to its transcript; current activity; and a reply field last. The status bar shows the active tab's label and, for a remote session, its host.

What should happen: switching tabs paints instantly with no await, fetch, or lazy enrichment. On an older CLI the cards degrade honestly: request falls back to the cleaned prompt and then the topic, timeline falls back to checkpoints, and the Files card does not appear. Two states are never faked: when no reset has been seen for the subject's scope the Timeline says "Waiting for the session stream…" and names the command; when the CLI reports the timeline unavailable it says so with the CLI's reason.

Manage a project from the left sidebar

You run several agents on one project and want the project's state in view while the right sidebar shows the session you are in: what is open, which sessions stopped, which PRs are ready, what is next.

The Project panel is one sidebar view with five icon tabs: Overview, Sessions, Pull requests, Tickets and, last, Settings (a gear). The active tab shows its label (and, for Sessions, how many are live), a badge on the Sessions icon counts sessions that need you as of the last time Sessions was shown (the stream runs only while Sessions is visible), arrow keys move between tabs, the panel remembers the active tab per workspace, and each tab keeps its scroll while the panel is open. Only the active tab loads. Its project is the one containing the open workspace folder (agents projects status --path <folder> --json), or the one you choose with Switch Project, remembered per workspace. Overview shows the project's progress, a bar of its open tickets by state (Doing, In Review, Todo, Backlog) with counts, and the current milestone with its due date; when no milestone is current it says so and how many open tickets have none. Sessions lists every session of the project from the session stream already in memory, filtered on the CLI's confirmedProject, so it starts no process; the stream is demanded only while Sessions is the visible tab, and it redraws when the stream changes. It is built to be read at a glance (AGENTS.md, Design). A header counts tabs in this window, live sessions and the ones that need you, beside a ⇅ menu with checkmarks: Sort (last active, newest, name), Show (tabs with no agent, ended) and Group (App, Machine, State, None); the choices, folded groups and hidden sessions are remembered per workspace. Ended sessions are shown by default in a folded Ended group (under App and State grouping), so a session to resume is one unfold away; preferences saved before this default get it too, unless they had turned Ended on or group by Machine or None, which have no Ended group and keep Ended off. Needs you is pinned above every grouping, ordered by the CLI's attention kind (question, permission, plan review, declared, failure, stall, review; ATTENTION_KIND_RANK, src/shared/sessionState.ts), then by the Sort choice. Grouped by App, each group is where the session lives, with the app's icon: this window (its workspace name, e.g. agents, and VSCodium), each other editor window by the workspace its tab's window has open (observerTerminals[].workspaceDir from the CLI), Ghostty (the row's terminal app), other terminals, Background (a headless run, a team member or a cloud task), and Tabs with no agent (an ended session whose tab is still open here, with Close all). A group header carries a count and one dot per state, so a folded group still says what is inside. Each session is an outlined card. At rest it is compact: the harness's logo (from the row's agent type) before its title, and how long since it last moved, a pill with its state as a dot and a word (named the same on every surface by sessionStateOf, src/shared/sessionState.ts: Needs you, Stopped, Working, Your turn, Unknown, Ended; the Working dot breathes, except under reduced motion), where it runs (machine and tab) with, at the right end of that line, the model the CLI reported for the latest reply (opus-5-5; no chip when the row has none), the agent's latest line or the question it is asking, and a strip with its PR, its ticket, a count of artifact folders and tiny images (dashed when you attached it). Hovering or selecting the card shows the full card: your last ask with the images you attached, marked attached; the agent's words, or its question in an amber box; the command it is running; and Made, what it produced: every PR, its ticket, and one entry per folder of artifacts with thumbnails of the images it rendered (from the same fields as the session sidebar, sessionCardFields). Hovering a small image floats a larger one labelled "Attached by you" or "Made by the agent". A click selects the session: the other sidebar shows it, and nothing opens. Going somewhere is an explicit icon on the card: focus (↗) brings its tab forward, or opens the live agent in the window that owns the project, the same resume as Agents: Resume Session…; resume (▶) on a tab whose agent exited. The list manages your tabs: × closes the session's tabs in this window (closing a tab ends the agent's process there; the session stays resumable), at once with Undo when the agent is idle or exited, and only after an inline confirmation when it is working or waiting on you. A session with no tab here gets an eye icon instead, which hides it until it moves again. ⌘- or Shift-click selects several cards for one Close N tabs. Pull requests lists every open PR across the project's repos (agents projects prs list <name> --json) with a ring for its checks (turning, a check, red, dashed for a draft) and the default branch's state, with recently merged ones listed below. Tickets lists the project's open Linear tickets (linear tasks --project <linear> --json) grouped by state, Doing first, each with priority bars. Clicking a ticket opens its detail in the panel with one linear tasks <ID> --json read on that click: identifier and state, title, assignee, milestone and Open in Linear ↗, a Start an agent on this ticket button, the description as minimal markdown (headings, bullets, bold, code, links; everything else escaped), the last three comments, and a comment box. Comment runs linear update <ID> --comment=<text> and rereads the detail. Start launches your default agent (Settings) in a new tab here through the same path as Agents: Spawn With Prompt, with the task Work on <ID>: <title> (<url>). ‹ Tickets returns to the list. Overview, Pull requests and Tickets read their verb when their tab is shown, at most once a minute, or on Refresh; an open ticket rereads only on Refresh; nothing polls. Settings holds AGI EXT's own preferences and reads nothing from the CLI: the six session-title toggles; shortcuts with the platform's modifier (⌘⇧A is New agent, where the CLI picks the harness; the default agent, used to start a ticket and by split launches; ⌘⇧B's second agent; ⌘⇧1 to ⌘⇧9 quick-launch slots, each an agent or none, a slot keeping its model until you change its agent); the Reader for .md and .html; and approval alerts with their style. Devices, accounts and projects live in the agents CLI and the AGI Menu. Approval alerts, off until you turn them on, page once each time a session with a tab in this window starts needing you, driven by the session stream whether or not any panel is open: a native OS notification (macOS, Linux) or an editor toast with Focus terminal.

What should happen: a slow read paints "Loading…" in its own view and never blocks the others; a failed read shows the CLI's error in that view; a project with no Linear project says how to link one.

Answer an agent that needs you

Some agent, on some machine, is waiting on you. You want to see exactly what it asked and answer it from the editor.

You open the Project panel's Sessions tab. Needs you is pinned above every grouping: every session of the project whose attention row the CLI feed marks open, ordered question, permission, plan review, declared, failure, stall, review, then by the Sort choice. Each card shows the agent's question in an amber box. Clicking the card makes it the Active Session sidebar's subject, which shows the same ask under its header with how long it has waited, Reply and Focus. Reply sends your text into the agent's tab in this window; focus (↗ on the card, Focus in the sidebar) brings the tab forward, or opens the live agent in the window that owns the project. Focusing an agent tab with an open ask shows the same sidebar card without the panel. Approval alerts, once you turn them on in Settings, page once when a session with a tab in this window starts needing you.

What should happen: the session leaves Needs you only when the feed removes the attention row, never optimistically. The extension classifies nothing: membership is attention.state === 'open', the order is attention.kind through ATTENTION_KIND_RANK (src/shared/sessionState.ts), and a stall is a CLI signal. A tab the stream has not indexed yet carries no attention and cannot enter Needs you from the client side.

Resume, fork, or move a session

You want to continue an earlier conversation, branch it into a sibling, or carry it to another machine or harness.

For resume you run Agents: Resume Session… (Cmd+Shift+Alt+R) and pick a session by name: no ids, no terminal. It lists this window's project's sessions on every machine, newest first, from the session stream already in memory (scoped by the CLI's confirmedProject, like the Project sidebar). Each row shows the title, the machine, your last message, the agent's last line, how long ago, and OPEN when a tab already shows it; typing filters by title or message. A row is still usable with only its id, title, machine and last activity. Enter runs agents.resumeSession: a tab already showing the session comes to the front, else the CLI opens the live agent in the window that owns the project. One VSCodium notification says where it went ("Opened … in svatlas", "Focused … in svatlas", or the reason it could not); nothing is printed inside the tab. The Project panel's focus (↗) and resume (▶) icons and the side panel's Focus and ↻ run the same action. Resume (Pick Host) reopens the active tab's session on a device you pick, same harness and version. Resume (Pick Harness) continues the active tab's session in a different harness on the same device through the universal /continue flow. Resume (Best Profile) (Cmd+Shift+Alt+J) rotates the active tab to the signed-in account with the most headroom.

For fork you run Agents: Fork, Fork (Recap), Fork (Pick Host), or Fork (Pick Session); all delegate to agents sessions fork <id>, which resolves the source across the fleet and launches a recap-seeded same-harness sibling. The original is untouched.

To move a session to another machine, Resume (Pick Host) reopens it on the device you pick. Moving a session's files and state between devices is agents sessions migrate in the CLI; the extension has no migrate gesture.

What should happen: each action is one command, the extension resolves only the selection, and the new tab rebinds from the stream. The extension never reproduces resume compatibility, account selection, placement, or fork identity rules.

Start an agent on a ticket

You have a ticket and want an agent on it without opening a terminal yourself.

In the Project panel's Tickets tab you click the ticket. Its detail opens in the panel from one linear tasks <ID> --json read: state, title, assignee, milestone, the description, the last three comments, and a comment box. Start an agent on this ticket opens your default agent (Settings) in a new tab here through the same path as Agents: Spawn with Prompt, with the task Work on <ID>: <title> (<url>). The new session joins the Sessions tab once the stream reports it with this project as its confirmedProject. A free-text task is Agents: Spawn with Prompt (Cmd+Shift+J); a dispatch to a worker you name is agents run in the CLI.

What should happen: the panel never scores devices or accounts; the launch is composed by buildAgentLaunchCommand like every other launch. A session the CLI has not confirmed for this project does not appear under it; the panel never guesses a project from a working folder, a branch or a prompt.

Reuse a terminal for a new session

You exit the agent in a tab and start another one in the same terminal. You expect the tab, the status bar, and the sidebar to follow the new session without opening a new tab.

You type exit or quit the agent, then launch another in the same Agents terminal. For a moment two stream rows may both claim the tab's stable observer terminal id. The extension treats two distinct live claims as ambiguous and keeps the existing binding. Once the old session is removed from the stream, or returns only as a Previous row, the new session is the sole live claim and the tab rebinds to it.

What should happen: no tab switch is needed; the status bar and the Active Session sidebar follow the new session, and a terminal-selected sidebar subject follows the exact terminal id across the rebind while a subject selected from the Project panel stays tied to its session. Start time is never an ownership signal. Reconciliation runs only on pushed reset and agent-row facts, never on a poll or a local state-file read, and it stays scoped to the terminal's observer device and execution host.

Commit with Autogit

You have staged or working changes and want a commit message in your own style, committed and pushed, in one action.

You press Cmd+Shift+G. The extension reads the git extension's repository state, builds the diff and the status summary while honoring the agents.ignoreFiles patterns, and asks agents run claude --model haiku for a message shaped by your agents.commitMessageExamples. It stages, commits, and pushes unless agents.disableAutocommit or agents.disableAutopush say otherwise.

What should happen: one keystroke, one generated message, one commit. The timeout is agents.commitGenTimeoutMs. No OpenAI key is involved; Autogit stopped using it when message generation moved to the CLI.

Read an artifact in the Reader

An agent produced a plan or a report as Markdown or HTML and you want to read it like a document, not as source.

You enable the Reader once with Agents: Reader (Enable). From then on .md files can open in the Notion-style editor (TipTap, with a frontmatter panel, outline, slash commands, callouts, toggles, file attachments) and .html files open in a sandboxed viewer. Both are registered as optional custom editors, so the default text editor stays available. A plan or report a session made opens in the Reader from the Active Session sidebar's Artifacts gallery, beside the agent that wrote it.

What should happen: the HTML viewer never runs the page's scripts against the editor; it renders inside the webview sandbox. A link in the page with an agents:, http(s): or mailto: address opens outside the editor, the same as a browser click: an artifact's "Open session" chip focuses the tab running that session. Other addresses never leave the viewer. Images and attachments dropped into the Markdown editor land in the agents.editor.assetFolder folder next to the document. Agents: Reader (Disable) restores the default association.

Requirements

Stream contract. Exactly one agents feed watch --json child exists per machine for all editor windows, owned by the elected leader window, and only while some window demands it: a visible Active Session sidebar or Project Sessions tab, an open Resume Session picker, or a tracked agent tab whose identity the stream has not resolved. When no window demands it the producer is torn down after a short grace period. Every window reads a broadcast projection of that stream. A reset replaces a scope; upserts and removes apply only when newer; a stale event is ignored; a follower that has never seen a reset renders as degraded, never as an authoritative empty state. If a field the UI needs is missing from the stream, the fix is to add it to the CLI's row, never a side-channel fetch. That side channel caused the 2026-08-25 CPU incident.

One-shot verbs. Launch, resume, fork, stop, merge, and a ticket comment are each built with the owning CLI noun and run once per user action. A merge from the sidebar is re-decided by the host from its own snapshot, confirmed in a modal, and pinned to the head SHA. No retry timers, no caches of CLI output beyond a short in-flight guard. Closing a tab tears the agent down only on a real user close.

Fail loud. A missing CLI binary is a visible prerequisite failure. A missing CLI noun is an upgrade error. A malformed feed event is rejected and reported without corrupting the current scope. No filesystem fallback fills a gap.

Active Terminal details and outputs. The header shows the account slot label when supplied by the CLI, with the account email on hover. Clicking the short session ID copies the full ID; every terminal subject, including one whose harness has not reported an id yet, also offers Set Session ID for Terminal. Focus and Resume are compact icon buttons. The ⋯ menu remembers its disclosure state and shows harness/version, full ID, cwd, branch and host. Files and Artifacts use host-formatted paths that preserve the complete filename, shorten owned scratch to its session-relative path, and expose full paths on hover. Artifacts contains numbered PRs, the CLI row’s planFile, documents and Linear issues; no local PLAN.md discovery occurs. File and URL rows support keyboard activation, and timeline rows expand in place.

Theme. The Active Terminal panel fills the viewport with the sidebar background, including empty space beneath short content. Over that ground it is drawn in the Rush register (rush/DESIGN.md, Day and Altitude), the same visual language as getrush.ai and artifacts-cli: section labels in Jost capitals, the interface in Inter, ids and numbers in the editor's monospace font, cards as glass with a one-pixel edge over a faint sky. A dark editor theme gets Altitude (white glass, zinc type), a light one gets Day (ivory glass, ink type), and a high-contrast theme keeps VS Code's own colors and borders. Gold marks only the primary action; status is a dot, a badge or a word, never a filled button; links are the text color, underlined. Every color comes from one token block keyed on the theme kind VS Code sets on the webview, and Jost and Inter ship inside the extension, so the panel loads no remote font.

Latency. Opening the sidebar, switching tabs, and selecting a Project panel card spawn zero subprocesses; the sidebar paints from the warm store synchronously, and the Sessions tab renders from the same store. Overview, Pull requests and Tickets read their verb when their tab is shown, at most once a minute, or on Refresh; an open ticket is one read on its click; nothing polls. A card draws only what its stream row carries, so a row with no reply shows none rather than a placeholder. Hovering or selecting a card adds your last ask, the agent's words and what it made, from the same fields as the sidebar (sessionCardFields); an artifact of a remote session opens by the same one-file copy the sidebar uses.

Launch composition. --cwd is emitted once, independently of device selection, for ordinary, Auto, Pick Host, Pick Account, local, and version-pinned launches, carrying the exact open workspace. Only Pick Project emits --project, and it never emits --cwd. --strategy balanced is emitted for every automatic-placement variant (default, Auto, Pick Host, Pick Project, local) and dropped for exactly two: the account picker (harness@), which is mutually exclusive with a strategy, and a pinned version, where the CLI ignores it. Ordinary launches never derive a target from agents projects view <cwd>.

Identity. Publisher swarmify and name swarm-ext in package.json never change; the swarm-ext:// URI the CLI emits names swarmify.swarm-ext as its authority, and the URI handler serves /focus (raise a tab), /inject (deliver text into a live terminal by session id), and /spawn (open an editor tab running a supplied command such as claude --resume <id>, which the agents-cli terminal engine's vscodium-agent backend uses to resume a session into this editor). A /spawn opens only in a window whose folders contain its project (a request without one is refused) and focuses the window's existing tab for that session rather than opening a second. agents.resumeSession(<id>) is the extension's one entry point for the same thing: it focuses this window's tab or has the CLI open the session in its project's window, and returns the ack status; with a nonce the window writes ~/.swarmify/agents/spawn-acks/<nonce>.json saying opened, focused-existing, wrong-window, or failed, so the CLI reports what happened instead of assuming. Display names may change freely.

Multi-window. Opening a second window must not double long-lived watchers, transcript parsing, or schedulers. Followers recover replayable session and attention state from the leader's replay cache. The Project panel's overview, pull requests, and tickets are still separate bounded CLI reads until the stream owns them; that is recorded debt.

Harness roster. The presented harnesses, their labels, prefixes, and install info derive from the CLI catalog through one shared module with a drift test; no hand-written harness list exists in the UI. Gemini is not presented.

Evidence

The suite runs with bun test --timeout 30000 from the repository root and exercises real command boundaries; the only sanctioned double is src/testing/vscodeDouble.ts. The baseline on this branch is 1,853 tests across 165 files with 6 failures, all in the UI package when run from the root, unchanged from origin/main. bun run lint:dead (knip) runs inside scripts/build.sh and fails the build on any unused file, export, type, or dependency. scripts/build.sh <version> must produce a VSIX, and a local scripts/install.sh followed by Agents: New Claude must open a tab with a live prompt. Agent-integration tests (bun run test:agent-integration) require the agents binary on the box and hit it for real.

The checks that matter for the journeys are the ones an agent or a person runs against the installed extension: one agents feed watch child across two windows; zero processes on a card click; tabs restored after reload with no session stopped; a permission prompt that joins Needs you with the harness's question and leaves on the feed's removal; a Pick Account launch that shows the worker's own picker.

Open decisions

Whether restore should move entirely into the CLI daemon, which would delete prewarm.simple.ts and the per-window restore file, is decided in principle (yes) and blocked on the CLI carrying a restore projection. Whether messageCount and recentFiles return to the sidebar depends on the CLI adding them to the stream row; a lazy enrich is not an option. Whether the Project panel's overview, pull request, and ticket reads move onto the stream is deferred until the CLI projects them. Switching the stream to agents sessions watch --json --local is rejected until the CLI side lands, because feed watch is the only producer of attention and activity events and the only fleet fan-out.

The Active Terminal Details disclosure includes branch and changed-file buttons that open Source Control. Timeline expansion persists across stream updates. Artifact types follow CLI buckets; remote paths never borrow the editor host’s home directory.
