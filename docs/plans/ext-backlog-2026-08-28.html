AGI EXT · Backlog Audit & Fix Plan · 2026-08-28

The extension keeps deriving what the CLI already knows.

I audited every open AGI EXT ticket against the code at HEAD (7f3311f) with four independent code sweeps. Five are already fixed — close them. Ten are real and open, plus seven new bugs the sweeps surfaced. Nearly all of them are the same root cause wearing different masks: the ext maintains its own session state — transcript parsers, per-tab side-channel spawns, local staleness clocks, a homegrown preview — instead of riding the single agents feed watch stream and the agents sessions preview --json verb the CLI already ships. The plan collapses those masks into four epics.

The root cause, in one picture

Epics 1 & 2 delete the four red side channels. Always-on identity (account, model) rides the stream row; the rich card is one agents sessions preview <id> --device <host> --json per user selection — which the CLI already ships. No new transport is invented; the ext stops guessing.

The four epics

Epic 1 — Delete the side channels

Ride the stream, stop spawning per tab

Kills the 2026-08-25 CPU-storm class at its root and shrinks the ext toward the thin-client contract.

  • PHNX-3184 — add account to the CLI SessionWatchRow (backfilled from the index like version), project it through sessionCliStream → sessionPresentationStore, read it in the status bar, then delete fetchSessionIdentity + tryHydrateSessionIdentity.
  • PHNX-2833 — rewrite agentPanel.vscode.ts buildSnapshot to read toolCallCount/todos/topic from the store; demote the 4s interval to a render tick. Fix stale comment N6.
  • PHNX-2484 — fold the duplicate foreman.sources.ts resolver into core/agentsBin.ts; strip the gemini branch from prewarm.simple.ts; retire sessionParse.ts/readinessDetector.ts in favour of stream fields. Staged deletions, each its own PR.
Epic 2 — The detail panel becomes the CLI card

Picker parity, with real loading & error states

  • PHNX-2973 — on selection, call agents sessions preview <id> --device <host> --json once; render version · model · account, token count, +N ~N -N changes, skills, hooks, links/PRs, tool histogram, tests, errors. Retires the ext's homegrown getSessionPreviewInfo.
  • PHNX-2976 — thread state: loading | ready | error into DetailPane: skeleton while the verb is in flight, an explicit error row on failure — distinct from an empty section. Fixes N3 (drop the local staleness clock; trust stream phase).
Epic 3 — The feed tells the truth

No confident-wrong states in the attention surface

  • PHNX-2975 — sort each rendered mixed-phase group by floorSort (renderRows(sortAgents(arr, floorSort))) so "Needs you first" actually floats waiting→failed→stalled above running. Fixes N4 (include needs-you in grouping).
  • PHNX-2735 — add resetSeen/lastResetAt to the store; a follower with no reset arms a one-shot re-request and renders a distinct stream-degraded state — never "0 sessions". Fixes N2 (filtered zero-state) and N1 (re-key attention).
  • PHNX-2978 — make cachedInFlight trailing-aware (one guaranteed final run after an in-flight burst) so the running→idle transition always lands.
Epic 4 — Reply & launch correctness

Every control does what it looks like it does

  • PHNX-2980 — thread the reply channel into StructuredReply; when kind==='none', replace chips/Send with the already-computed reason up front ("Runs on yosemite-s1 — open it there to reply").
  • PHNX-2553 — mint a Claude session id in launchAgent and thread it through buildNewAgentLaunchCommand + registerAgentTerminal, consolidating id-minting so the two launch paths can't drift again.
  • N5/N7 — delete the dead onAttach chain and the stale ssh/tmux comments. Screenshot attach returns only when a CLI verb accepts an attachment — fail loud until then.

Sequencing

  1. Close the 5 done tickets with a file:line evidence comment on each. — reversible, and each was independently verified at HEAD.
  2. Epic 4 first (ext-only, self-contained): PHNX-2980 + PHNX-2553 + N5/N7 cleanup — one PR, fast win, no CLI dependency. Ships the "every control works" story with a screen recording.
  3. Epic 3: PHNX-2975 + N4, then PHNX-2735 + N1/N2, then PHNX-2978 — feed-truth fixes, ext-only, each with a floorModel test.
  4. Epic 1 CLI half: add account (+ any missing card fields) to SessionWatchRow in agents-cli — one PR there, since it's a fleet-wide stream change.
  5. Epic 1 ext half + Epic 2: consume the enriched stream, wire preview --json into DetailPane, then delete the side channels (3184, 2833, 2484) and the homegrown preview. Deletions land only once their replacement is proven.
Guardrails carried through
Every change is a worktree + PR under .agents/worktrees/; non-author review before merge; each behavior ships with a real-path test (no mocking beyond the shared vscode double); CHANGELOG + AGENTS.md/README updated when behavior changes. CLI stream changes go through agents-cli's own release train. No new scheduler, no new side channel — the ext only ever renders CLI state and calls CLI verbs.
