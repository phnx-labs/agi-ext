## What this is

AGI EXT is the VS Code and VSCodium extension for [agents-cli](https://github.com/phnx-labs/agi-cli). It turns an open-source editor into an integrated agents environment: every coding agent (Claude Code, Codex, OpenCode, Cursor, Antigravity, Grok, Kimi, Droid) runs as a full editor tab, the Active Session sidebar shows what the focused agent is doing, and the Project panel lists every session of the open project on every machine you own, the ones that need you pinned first, beside the project's pull requests and tickets. The editor becomes the place you steer a fleet from, the way it used to be the place you typed code.

The extension is a presentation layer. agents-cli owns every fact (sessions, devices, accounts, attention, activity) and every mechanism (launch, placement, resume, fork, stop, scheduling, watchdog). The extension renders what the CLI streams and turns a gesture into exactly one CLI verb. That split is the product's one architecture rule and the source of almost every requirement below.

It is for developers who already run several agents at once, usually across more than one machine, and who want to see and steer that work without leaving the editor. It is a private repository shipped publicly on the Marketplace and Open VSX under the frozen identity `swarmify.swarm-ext`.

## Summary

Open the editor, press one chord, and an agent starts on the right machine with the right account, in the folder you have open. Look at the sidebar and know what it asked, what it did, and what is left. Open the Project panel and see every agent on the project wherever it runs, reach the ones waiting on you, and start an agent on the next ticket. Close the laptop, come back, and the tabs are exactly where you left them. None of that starts a poller, parses a transcript, or invents a status.

## Goals

**An agent starts from the editor without a prompt.** `Agents: New <Harness>` opens a tab and the agent is running on a fleet worker with a balanced account in the open workspace. Check: press Cmd+Shift+A on a workspace, watch the tab open with `agents run <harness> --interactive --device auto --cwd <workspace> --strategy balanced --mode auto` and a live prompt inside it, with no picker shown.

**The editor never invents a status.** Every phase, needs-you flag, label, and timeline step shown comes from a row the CLI streamed. Check: with the stream stopped, the sidebar says "Waiting for the session stream…" and names the command it expects instead of showing an empty card.

**Seeing costs nothing.** Selecting a Project panel card, switching tabs, and opening the sidebar spawn no process. Check: `ps` shows exactly one `agents feed watch --json` child for all windows while the Active Session sidebar or the Project panel's Sessions tab is visible, and none when neither is.

**Tabs survive the editor.** Reload, crash, or quit and the agent tabs come back bound to their live sessions. Check: reload the window with three agent tabs open; three tabs return with their labels, and none of the sessions were stopped.

**Every session of a project is one list.** The Project panel's Sessions tab shows local, remote, background, and ended sessions with the same card shape and the same needs-you rule. Check: a session of this project started on a worker box by another machine appears in the panel with its machine on the card, and focus (↗) opens it in the window that owns the project.

**A person sees what is asked from where they are.** A permission, question, or plan review pins its session to Your move (asks) in the Project panel with the agent's own question, and the Active Session sidebar shows the same ask under its header with Reply and Focus. Check: trigger a permission prompt in a tab; the session joins Your move with the harness's question, and it leaves only when the CLI removes the attention row.

## Non-goals

**No scheduler in the extension.** Nothing in the extension launches, resumes, kills, injects, or rotates anything on a timer. The CLI daemon is the only scheduler. A second scheduler in a UI process caused the resume storms and the 31 percent idle CPU incident the current design exists to end.

**No transcript parsing or local state reads for facts.** The extension does not read `~/.claude/projects`, terminal registries, or session state files to decide anything the stream can carry. Remaining readers (`src/monitor/sessionParse.ts`, `src/monitor/readinessDetector.ts`) are recorded debt, scheduled for deletion, never extended.

**No second platform.** The extension does not score devices or accounts, resolve project paths, decide fork identity, or reproduce resume compatibility. Each of those has one owner in the CLI and the extension calls it.

**No second session preview.** The Project panel is a list whose cards select; the Active Session sidebar is the one session preview. The deleted Fleet dashboard's persisted detail-rail preference produced a blank third-width column on open, and two previews of one session drifted.

**No Gemini integration.** The extension has no Gemini launch definition, installer, watchdog registration, prewarm configuration, transcript parser, or context-file alias target. Opening a workspace never creates `GEMINI.md`, even when an old explicit alias mapping requests it. Existing files remain untouched. Other configured aliases still work. The CLI catalog snapshot retains legacy ids solely to match the CLI protocol, not to install or offer the retired harness.

**No local-first execution path or silent fallback.** A launch under the default target goes to the fleet worker pool. A missing CLI noun is an upgrade error, never a filesystem fallback.

**No API keys held by the extension.** Autogit generates commit messages through `agents run claude --model haiku`. The Foreman voice orb and its `agents.openaiApiKey` setting were deleted with the Fleet dashboard in 0.9.394.

## Findings

Three observations from running the extension shaped these requirements more than any design preference.

An always-on session watcher was removed in August 2026 because it pinned about 31 percent of a CPU core and leaked ssh fan-out to feed a view nobody had open. Restoring it behind a demand gate, so the single producer exists only while a visible sidebar or Project Sessions tab, an open Resume picker, or an unresolved tab needs it, is what made the stream affordable again. The same month a side-channel fetch per row produced the CPU incident recorded as agi-cli#3019; that is why a missing field goes onto the CLI row and never into a client fetch.

A persisted "detail rail open" preference in the Fleet dashboard (deleted in 0.9.394) restored a blank third-width column on open with nothing selected, and two previews of one session (the rail and the sidebar) drifted from each other. Removing the rail and making the sidebar the one preview removed the whole class of defect.

Ordinary launches once resolved the workspace through `agents projects view <cwd>`, and the first weak match in a monorepo silently sent the terminal to a child project's default path. Emitting the exact open workspace as `--cwd` and reserving `--project` for the explicit Pick Project command fixed it, and a recovery mapping that was machine-global instead of per-workspace produced a multi-window resume storm on reload. Both are now invariants enforced in code and tests.

## Start an agent in a tab

You are in a workspace and want an agent working on it now, without deciding where it runs or which account it uses.

You press Cmd+Shift+A, or pick `Agents: New Claude` (or any presented harness) from the palette. The extension reads the one setting that matters, `agents.launch.defaultTarget`, and builds one command. Under the default `auto` that command is `agents run claude --interactive --device auto --cwd <workspace> --strategy balanced --mode auto` (the tests in `src/core/launchTarget.test.ts` assert the same string without the workspace). The workspace is passed exactly as opened: a monorepo root stays the root and a nested project folder stays that folder, locally and remotely. A tab opens named `CL` and the CLI places the run on a device from the worker pool, rotating the account by usage headroom.

When you want to choose one axis and let the CLI balance the other, the harness has five explicit variants. `(Local)` emits `--local --cwd <workspace> --strategy balanced --mode auto`, pinning the launch to the editor’s machine regardless of the configured target. Local defaults and Pick Host’s This Machine choice also emit `--local`. A hostless version pin emits `--local` and omits `--strategy`; an explicit host still wins. `(Pick Host)` prompts for the device and emits `--device <name> --cwd <workspace> --strategy balanced --mode auto`. `(Pick Account)` emits `claude@ --interactive --device auto --cwd <workspace> --mode auto`, with no `--strategy`, so the CLI routes to a picker-eligible worker and shows that device's account picker in the tab; a signed-out account can be chosen and authenticates in place. `(Auto)` chooses both without a prompt, ignoring the configured target, and emits the same `--device auto --cwd <workspace> --strategy balanced --mode auto` as the default. `(Pick Project)` is the only variant that replaces the workspace: it shows a project quickpick and emits `--device auto --project <slug> --strategy balanced --mode auto`, and the CLI resolves the project's configured path on the chosen worker. `--strategy balanced` rides every automatic-placement variant; only the account picker and a pinned version drop it.

What should happen: within a second a terminal tab exists, the status bar shows the agent's label and, when it runs elsewhere, the executing host shortened to its unique suffix. The tab title, the session's card and the status bar show one name: the CLI's resolved `title`, else its label (your `/rename`), else the topic or request (`streamTitle`, `src/core/projectPanel.ts`); the extension generates no name of its own and no longer reports a tab's title back to the CLI. When the CLI says what a session was started with (`startedAs`), its card shows it on a faint "started: …" line. Agents: Rename Session (Cmd+Shift+L) renames the session itself: it types Claude's `/rename <name>` into the tab, and the new name comes back through the stream; other harnesses have no rename the CLI reads, and the command says so. The picker and `--strategy` never appear together; `--project` and `--cwd` never appear together. These exclusions are enforced by `buildAgentLaunchCommand` in `src/core/agents.ts`.

## Come back after a reload or a crash

You closed the editor, or it crashed, with agent tabs open. You want them back exactly as they were, and you want none of the agents killed by the reload itself.

You reopen the workspace. The extension reads the persisted tab metadata for that workspace (terminal id, harness prefix, session id, host, label, pinned version) and reopens each tab through the CLI's resume path. Each restored tab then rebinds from the live stream: the first row that claims the tab's terminal id on the same observer device and host is the tab's session.

What should happen: every tab returns with its label and icon; the status bar and sidebar follow the restored session once the stream reports it; the agent process was never signaled. Closing a tab by hand is different: only a real user close (`TerminalExitReason.User`) issues `agents ps stop <id>`. A reload is never treated as a close. Each window keeps its tabs in its own file, so a second window can neither resurrect a tab you closed nor erase this window's tabs; restore opens one tab per session, keeps each tab's device, and skips a session the window already shows.

Where this is still debt: `src/core/prewarm.simple.ts` still lists OpenCode sessions on tab open, slated for deletion once the CLI daemon owns restore.

## See what an agent is doing

The active agent tab shows a copy icon and the first eight characters of its session ID. Hover exposes the full ID and remote host; clicking copies the full canonical ID. Switching to a text editor or a plain terminal clears the session tooltip. Remote attach titles omit host-only placeholders; execution host identity comes from structured stream facts, never task text.

You have several tabs and you want to know, for the one you are looking at, what you asked, what it has done, and whether it is stuck, without scrolling its terminal.

You focus an agent tab, or click a session card in the Project panel. The Active Session sidebar (the `agentsPanel.terminal` view) takes that session as its subject; the last of the two triggers wins. A focused tab whose harness has not reported its session id yet (Codex, Grok) is still the subject: the sidebar shows that tab, never the previously focused one, and renders its row once the stream binds the id or you set it with Set Session ID for Terminal. The sidebar renders synchronously from the warm presentation store as one card, top to bottom (owner review, 2026-10-12: fewer components, nothing important below the fold). The title line carries the harness icon, the session's title (your `/rename`, else the CLI's generated title) and three quick icons, each with its words in its tooltip: open its tab (↗; ▶ resume when no tab here holds it), fork (⑂: the panel's own tab forks in place, otherwise Agents: Fork (Pick Session)), and `⋯`, a drawer inside the card with the model, the account label, the host, the short session id (copy, and a pencil to rebind the tab, offered even before the harness reports an id), chips for project, branch, a `worktree` badge only when the agent works in a linked worktree, the start time, tokens, and the raw identity lines; the drawer remembers whether it is open. Under the title one line states where the session is, by who has the ball (`sessionStateOf`, `ballOf`, the same words the Project panel uses): "Asks" (an open question or permission), "Stuck" (the CLI flags a live stall or failure), "Ready for review", "Idle" (it finished its turn and asked nothing), "Running", "Waiting" (its turn ended but its own background work still runs; a slowly breathing blue dot, and under the state a "Waiting on its own work" list names each subagent, background shell and monitor with how long it has run), or "Ended" (the process exited or is gone; it says nothing about whether the work succeeded), with how long it ran, when it last moved and, quiet at the end, the account it runs on. Asks and Stuck read amber. A Running session with no activity for five minutes shows "Running, but quiet since <time>" with Open; the line is rendered with the row and revealed by a CSS animation delay, so the sidebar keeps no timer. Failed and policy-blocked tool calls stay behind one quiet line ("⚠ 6 failed · 12 blocked") that appears only when there are any and opens to the list. The goal follows as one line. When the agent's latest status post (`agents feed post`) says it is blocked and you have not written since, the state reads "Blocked" in red and a strip shows the agent's own title and words with Reply and Open tab. Then an open ask with its own words, how long it has waited, Reply and Focus. Request shows your avatar (fetched from Gravatar by a hash of your email) and name, your sentence (two lines), thumbnails of images you pasted (also when the agent runs on another machine), and the whole turn behind a fold. **Made** follows: one row of previews you scroll sideways. The session's PR leads, read at a glance: GitHub mark, `#number`, one status word (Ready, Checks running, Failing, Conflicts, Changes requested, Needs review, Checks passed, Draft, Merged, Closed; `prVerdict`, the word and color the Project panel card's PR chip shows too, so a PR with green checks and a conflict reads Conflicts on both), the title, and a bar with one segment per check and the count passed (6/6). A click opens the PR's GitHub page as an editor tab (see Open a PR or ticket as a tab); nothing unfolds under the row (owner video, 2026-10-12). Merging is in `⋯`: the PR's review and merge glyphs, at most one action decided from the row (Merge when ready, Merge when green while checks run), confirmed in a dialog and run as one `agents projects prs merge|automerge … --sha <head>` pinned to the head commit shown, and Merge ▾, which reads that PR once and offers squash, rebase or a merge commit (`--method`) when GitHub would merge it, and an admin merge that bypasses branch protection (`--admin`) only when you are an admin of a repo that allows the bypass, run only after its own warning dialog and a second read confirming the head did not move (the same flow as a Project panel PR row); without a head commit it offers nothing and says why. The session's other PRs follow, then its ticket as a tile with its title and state when this window has read them (the Issues list or the ticket's detail; the row carries only the id, and the tile never reads Linear itself), which opens the ticket in the Project panel's Issues tab. Then every artifact file the CLI lists, newest first: an image as a downscaled preview (decoded once in the webview and cached), a page or document by its type mark, each with its name, type and age; a tile opens the file (a plan or report as an editor tab in the Agents Reader beside the agent that wrote it; for an agent on another machine the file is copied here first, the tile saying it is opening while it copies; a copy that fails says why in full, and a file from an agent worktree that was since removed names the worktree and where the merged copy is). A page, document or image on this machine carries Share on hover: it asks who can open the link (Rush org, Only me, Anyone with the link), runs `artifacts share <file> --visibility <org|me|unlisted> --json` once, copies the URL and offers Open; a refusal (a file with emails or credential-shaped strings) is shown as the CLI words it. Under Made, one Related line of chips names up to three other sessions to handle together with this one: the same ticket or PR first, then the same branch in the same folder, then a similar title or request (only the words that set a session apart count; words most sessions share are ignored). Each chip carries its state dot and, in its tooltip, why it is related; a click makes it the subject. It is a selector over the rows already in the presentation store (`relatedSessions`), so it starts no process. Last comes the activity strip and the feed it filters. The strip shows tool activity across the whole session, idle stretches collapsed into labeled gaps and markers for your messages, subagents and the open ask; clicking a bar jumps to that moment, and dragging across bars chooses any range (remembered per session; it lapses if it no longer lies inside the strip), shown as "<duration> selected ×". Bars outside the range dim, Made tiles changed outside it dim in place, and the feed lists only what falls in it. A stretch whose steps are older than the row's last few says so instead of looking empty. A turn the harness wrote for itself (a background task's `<task-notification>`, a `<system-reminder>`) is never shown as your message, as a step, or as the agent's current activity, and its marker leaves the strip so marker N and turn N stay the same turn. Chips switch the feed: All (newest three steps and the agent's status posts by time, the live line, failures and milestones; "N more" stays open across updates), Updates (the agent's `agents feed post` posts, from the stream's activity events, with their links; a blocked post reads red), You, Failed, or, one `sessions <id> --include` call per click, the agent's messages, tool calls or reasoning; and, when the row has them, Files (the changed files with the true total, as a tree in which a folder with a single child folder folds into one row, or as a flat list, marked with Source Control's A, M and D), Subagents (type, model, how long it ran and its tool count, running first, finished ones beyond the newest three folded, each opening to what it was asked, its verdict and a link to its transcript) and Checklist. With a range chosen on a local session, Show tool calls loads the calls once and draws them as a zoomed lane over the range. The reply field floats over the bottom of the panel, so it is in reach without scrolling. It is built once and never redrawn, so an update never takes its caret or what you typed, and a draft belongs to its session. Its mic dictates: click to talk, click again to stop, and the words land in the field to edit before Enter sends. It records the default microphone with `ffmpeg` and transcribes on this machine with whisper.cpp's `whisper-cli` and the `agents.dictation.model` model; nothing leaves the machine, and a missing tool, model or microphone permission is said in the field. A stream update patches the card in place rather than rebuilding it (`patchChildren`), so nothing jumps, hover stays, and a scrolled strip or an open fold stays as you left it (owner video, 2026-10-12). ‹ › at the top go back and forward through the sessions the sidebar showed (a Project panel card, a Related chip or a tab switch each leave a stop) and name where Back leads. The status bar shows the active tab's label and, for a remote session, its host.

What should happen: switching tabs paints instantly with no await, fetch, or lazy enrichment. On an older CLI the cards degrade honestly: request falls back to the cleaned prompt and then the topic, timeline falls back to checkpoints, and the Files card does not appear. Two states are never faked: when no reset has been seen for the subject's scope the Timeline says "Waiting for the session stream…" and names the command; when the CLI reports the timeline unavailable it says so with the CLI's reason.

## Talk to the project's Lead

You want to ask "what is waiting on me?" or say "put Claude on PHNX-4365" without finding the right session first. The Lead is one long-lived headless Claude per project that agents-cli runs (`agents lead …`); it answers from the fleet CLIs' output and dispatches agents. The extension is one of its thin clients, the docked one.

⌥Space works anywhere in the window: the editor, the sidebars and the integrated terminal, where agent sessions run (the extension adds `agents.lead.ask` and `agents.lead.talk` to the default of `terminal.integrated.commandsToSkipShell`; if you set that list yourself, add both to it). A window manager that takes ⌥Space for itself (some Linux desktops) keeps it. VS Code reports no key release, so holding the key counts as one press. It opens VS Code's own quick input at the top center, titled "Lead · <project> · <state>" (busy, with the busy bar, while the Lead works). Type and press Enter (the first row reads "Ask the Lead: “…”"), or press ⌥Space again (or the mic button) to talk: the reply box's dictation records on this machine and the words are sent when you stop. The rows are the current turn only: one per tool the Lead runs, a spinner while it runs and a check when done; the answer, one row per sentence (Enter opens the Lead tab); then one row per ticket, PR and session it named, with the Linear mark, the GitHub mark or the agent's icon. A ticket opens in Issues (its row's button opens its Linear page as a tab), a PR's GitHub page as a tab, a session in its tab or resumed through the same path as the focus icon. Anything destructive arrives as a Confirm row whose ✓ button (or Enter) runs `agents lead confirm <token>`. Esc closes the overlay; the turn keeps running, and its summary lands in the status bar. Esc while you are talking drops the recording and sends nothing; the reply box's own recording is never touched, and the Lead's mic stays off while the reply box records. A turn that prints nothing for 120 s, or runs past 15 minutes, is stopped and says so. `agents.lead.ask` also takes the text to send, for any caller that has it.

The status bar shows "✳ Lead · <last summary> · <age>", a spinner while a turn runs. Clicking it opens the Lead tab, "✳ Lead · <project>": the history (`agents lead history --project <p> --json`) plus this window's live turns, with ticket ids, PR numbers and session titles as links, tool receipts and Confirm buttons; beside it the Lead's session id, engine, model, the brief it started with, its memory and the tools it may run (`agents lead status --project <p> --json`). Both are read when the tab opens and on Refresh, never on a timer. `vscode://swarmify.swarm-ext/lead` opens the same tab, so FastWispr's bubble can hand over to it.

The status bar's hover offers Float as a bubble (also the command "Lead: Float as a bubble"; VS Code gives extensions no right-click menu on a status-bar item). It writes `~/.agents/lead/surface.json` `{"surface":"bubble"}`, which both clients watch: while it says bubble, ⌥Space belongs to FastWispr and the extension keeps only the status-bar item and the tab; "Lead: Dock into VSCodium" writes `"docked"` and takes the key back. With no file, the extension is docked; a file it cannot read keeps the last value it saw. Nothing is created until you choose a surface. The extension watches `~/.agents/lead` and `~/.agents` (so it follows the folder being removed and recreated, which a macOS watcher alone misses) and also rereads the few-byte file every 2 s, so a change made by FastWispr lands within 2 s even when an event is lost.

What should happen: one turn at a time per window; a second ask while one runs is refused with a note. A CLI that dies mid-turn ends the turn with its stderr; a CLI without `agents lead` is an upgrade error. The extension never starts, keeps or stops the Lead's process.

## Resume, fork, or move a session

You want to continue an earlier conversation, branch it into a sibling, or carry it to another machine or harness.

For resume you run `Agents: Resume Session…` (Cmd+Shift+Alt+R) and pick a session by name: no ids, no terminal. It lists this window's project's sessions on every machine, newest first, from the session stream already in memory (scoped by the CLI's `confirmedProject`, like the Project sidebar). Each row shows the title, the machine, your last message, the agent's last line, how long ago, and OPEN when a tab already shows it; typing filters by title or message. A row is still usable with only its id, title, machine and last activity. Enter runs `agents.resumeSession`: a tab already showing the session comes to the front, else the CLI opens the live agent in the window that owns the project. One VSCodium notification says where it went ("Opened … in svatlas", "Focused … in svatlas", or the reason it could not); nothing is printed inside the tab. The Project panel's focus (↗) and resume (▶) icons and the side panel's Focus and ↻ run the same action. `Resume (Pick Host)` reopens the active tab's session on a device you pick, same harness and version. `Resume (Pick Harness)` continues the active tab's session in a different harness on the same device through the universal `/continue` flow. `Resume (Best Profile)` (Cmd+Shift+Alt+J) rotates the active tab to the signed-in account with the most headroom.

For fork you run `Agents: Fork`, `Fork (Recap)`, `Fork (Pick Host)`, or `Fork (Pick Session)`. The first three delegate to `agents fork <id>`, which resolves the source across the fleet and launches a recap-seeded same-harness sibling. `Fork (Pick Session)` starts the same harness in the picked session's folder, on the machine it lives on, and types `/continue <id>` into it. The original is untouched. The new tab is named "fork of <title>" before it starts, keeps that name until the fork's own title arrives, and reads "fork failed: <title>" when the fork command exits nonzero (seen through shell integration).

To move a session to another machine, `Resume (Pick Host)` reopens it on the device you pick. Moving a session's files and state between devices is `agents ps migrate` in the CLI; the extension has no migrate gesture.

What should happen: each action is one command, the extension resolves only the selection, and the new tab rebinds from the stream. The extension never reproduces resume compatibility, account selection, placement, or fork identity rules.

## Reuse a terminal for a new session

You exit the agent in a tab and start another one in the same terminal. You expect the tab, the status bar, and the sidebar to follow the new session without opening a new tab.

You type `exit` or quit the agent, then launch another in the same Agents terminal. For a moment two stream rows may both claim the tab's stable observer terminal id. The extension treats two distinct live claims as ambiguous and keeps the existing binding. Once the old session is removed from the stream, or returns only as a Previous row, the new session is the sole live claim and the tab rebinds to it.

What should happen: no tab switch is needed; the status bar and the Active Session sidebar follow the new session, and a terminal-selected sidebar subject follows the exact terminal id across the rebind while a subject selected from the Project panel stays tied to its session. Start time is never an ownership signal. Reconciliation runs only on pushed reset and agent-row facts, never on a poll or a local state-file read, and it stays scoped to the terminal's observer device and execution host.

## Requirements

**Stream contract.** Exactly one `agents feed watch --json` child exists per machine for all editor windows, owned by the elected leader window, and only while some window demands it: a visible Active Session sidebar or Project Sessions tab, an open Resume Session picker, or a tracked agent tab whose identity the stream has not resolved. When no window demands it the producer is torn down after a short grace period. Every window reads a broadcast projection of that stream. A reset replaces a scope; upserts and removes apply only when newer; a stale event is ignored; a follower that has never seen a reset renders as degraded, never as an authoritative empty state. If a field the UI needs is missing from the stream, the fix is to add it to the CLI's row, never a side-channel fetch. That side channel caused the 2026-08-25 CPU incident.

**One-shot verbs.** Launch, resume, fork, stop, merge, and starting on a ticket are each built with the owning CLI noun and run once per user action. A merge from the sidebar is re-decided by the host from its own snapshot, confirmed in a modal, and pinned to the head SHA. No retry timers, no caches of CLI output beyond a short in-flight guard. Closing a tab tears the agent down only on a real user close.

**Fail loud.** A missing CLI binary is a visible prerequisite failure. A missing CLI noun is an upgrade error. A malformed feed event is rejected and reported without corrupting the current scope. No filesystem fallback fills a gap.

**Active Terminal details and outputs.** The header shows the account slot label when supplied by the CLI, with the account email on hover. Clicking the short session ID copies the full ID; every terminal subject, including one whose harness has not reported an id yet, also offers Set Session ID for Terminal. Focus and Resume are compact icon buttons. The `⋯` menu remembers its disclosure state and shows harness/version, full ID, cwd, branch and host. Files and Artifacts use host-formatted paths that preserve the complete filename, shorten owned scratch to its session-relative path, and expose full paths on hover. Artifacts contains numbered PRs, the CLI row’s planFile, documents and Linear issues; no local PLAN.md discovery occurs. File and URL rows support keyboard activation, and timeline rows expand in place.

**Theme.** The Active Terminal panel fills the viewport with the sidebar background, including empty space beneath short content. Over that ground it is drawn in the Rush register (`rush/DESIGN.md`, Day and Altitude), the same visual language as getrush.ai and artifacts-cli: section labels in Jost capitals, the interface in Inter, ids and numbers in the editor's monospace font, cards as glass with a one-pixel edge over a faint sky. A dark editor theme gets Altitude (white glass, zinc type), a light one gets Day (ivory glass, ink type), and a high-contrast theme keeps VS Code's own colors and borders. Gold marks only the primary action; status is a dot, a badge or a word, never a filled button; links are the text color, underlined. Every color comes from one token block keyed on the theme kind VS Code sets on the webview (`RUSH_THEME_CSS`, which the Project panel reads too, with the same outlined card and the same state dot colors), and Jost and Inter ship inside the extension, so the panel loads no remote font. A harness logo is drawn from its `.hx-<harness>` class in both sidebars, so a light theme gets the logo's light variant.

**Latency.** Opening the sidebar, switching tabs, and selecting a Project panel card spawn zero subprocesses; the sidebar paints from the warm store synchronously, and the Sessions tab renders from the same store. Issues and Review read their verb when their tab is shown, at most once a minute, or on Refresh; an open ticket is one read on its click; nothing polls. A card draws only what its stream row carries, so a row with no reply shows none rather than a placeholder. Hovering or selecting a card adds your last ask, the agent's words and what it made, from the same fields as the sidebar (`sessionCardFields`); an artifact of a remote session opens by the same one-file copy the sidebar uses.

**Launch composition.** `--cwd` is emitted once, independently of device selection, for ordinary, Auto, Pick Host, Pick Account, local, and version-pinned launches, carrying the exact open workspace. Only Pick Project emits `--project`, and it never emits `--cwd`. `--strategy balanced` is emitted for every automatic-placement variant (default, Auto, Pick Host, Pick Project, local) and dropped for exactly two: the account picker (`harness@`), which is mutually exclusive with a strategy, and a pinned version, where the CLI ignores it. Ordinary launches never derive a target from `agents projects view <cwd>`.

**Identity.** Publisher `swarmify` and name `swarm-ext` in `package.json` never change; the `swarm-ext://` URI the CLI emits names `swarmify.swarm-ext` as its authority, and the URI handler serves `/focus` (raise a tab), `/inject` (deliver text into a live terminal by session id), and `/spawn` (open an editor tab running a supplied command such as `claude --resume <id>`, which the agents-cli terminal engine's `vscodium-agent` backend uses to resume a session into this editor). A `/spawn` opens only in a window whose folders contain its `project` (a request without one is refused) and focuses the window's existing tab for that session rather than opening a second. `agents.resumeSession(<id>)` is the extension's one entry point for the same thing: it focuses this window's tab or has the CLI open the session in its project's window, and returns the ack status; with a `nonce` the window writes `~/.swarmify/agents/spawn-acks/<nonce>.json` saying `opened`, `focused-existing`, `wrong-window`, or `failed`, so the CLI reports what happened instead of assuming. Display names may change freely.

**Multi-window.** Opening a second window must not double long-lived watchers, transcript parsing, or schedulers. Followers recover replayable session and attention state from the leader's replay cache. The Project panel's overview, pull requests, and tickets are still separate bounded CLI reads until the stream owns them; that is recorded debt.

**Harness roster.** The presented harnesses, their labels, prefixes, and install info derive from the CLI catalog through one shared module with a drift test; no hand-written harness list exists in the UI. Gemini is not presented.

## Evidence

The suite runs with `bun test --timeout 30000` from the repository root and exercises real command boundaries; the only sanctioned double is `src/testing/vscodeDouble.ts`. The baseline on this branch is 1,853 tests across 165 files with 6 failures, all in the UI package when run from the root, unchanged from `origin/main`. `bun run lint:dead` (knip) runs inside `scripts/build.sh` and fails the build on any unused file, export, type, or dependency. `scripts/build.sh <version>` must produce a VSIX, and a local `scripts/install.sh` followed by `Agents: New Claude` must open a tab with a live prompt. Agent-integration tests (`bun run test:agent-integration`) require the `agents` binary on the box and hit it for real.

The checks that matter for the journeys are the ones an agent or a person runs against the installed extension: one `agents feed watch` child across two windows; zero processes on a card click; tabs restored after reload with no session stopped; a permission prompt that joins Your move with the harness's question and leaves on the feed's removal; a Pick Account launch that shows the worker's own picker.

## Open decisions

Whether restore should move entirely into the CLI daemon, which would delete `prewarm.simple.ts` and the per-window restore file, is decided in principle (yes) and blocked on the CLI carrying a restore projection. Whether `messageCount` and `recentFiles` return to the sidebar depends on the CLI adding them to the stream row; a lazy enrich is not an option. Whether the Project panel's overview, pull request, and ticket reads move onto the stream is deferred until the CLI projects them. Switching the stream to a local journal tail is rejected until the CLI side lands, because `feed watch` is the only producer of attention and activity events and the only fleet fan-out.

The Active Terminal Details disclosure includes branch and changed-file buttons that open Source Control. Timeline expansion persists across stream updates. Artifact types follow CLI buckets; remote paths never borrow the editor host’s home directory.
