Focus for review

The genuine decisions — everything else follows from these:

  1. Status model. A session is active (working), idle (running but stopped — waiting on your input / a permission prompt), waiting (waiting on a tool/CI), blocked (needs a decision only you can make), done/previous (ended). Filter chips and Group-by-Status use this taxonomy. Confirm the words.
  2. Grouping. Bring back a Group control that actually works: Project · Device · Status · None. (Today "Group Project" is shown but the Previous list is flat.)
  3. Resume semantics. A plain, compact Resume that reopens the session on the machine it ran on (not copied to your Mac). Right-click → "Resume on a different device…" for the power case. Drop the second "Resume here" and the oversized labeled button.
  4. THE ASK source. The real first user message, not the recap header ("## Apps"). If the stream only carries the header, this needs one new field on the CLI row (firstUserMessage) — a small CLI change, not a rebuild.

Current architecture

All of this is render-layer in SessionsPane.tsx reading the streamed FloorAgent, except two data gaps worth calling out. The row already carries prUrl; a repo URL and a Linear ticket URL are derivable (repo from prUrl; Linear from the ticket id + the workspace). The real first user message may not be on the stream — prompt/topic can be a slash-command header — so #1 may need a firstUserMessage field added to the CLI's SessionWatchRow (backfilled from the index, the way version landed), never a side-channel fetch here.

Status model

Status Dot Means Chip / group
active green working, making progress Active
idle amber running but stopped — waiting on your input or a permission prompt Idle
waiting amber waiting on a tool / CI to return (folds into Idle unless you want it split)
blocked red needs a decision only you can make Blocked
previous grey ended, resumable from transcript (the Previous band)

Timing model

  • Row age: always relative to last activity — 9m ago, 2h ago, 3d ago.
  • Card meta: Ran <duration> · ended <relative> ago, with the absolute range (Aug 30, 4:42–4:44 PM) on hover. duration = lastActivity − started; when it's <1m show Ran <1m. Never show two identical timestamps.

Public Interface

  • Row: logo only (no agent-name text); title is the recap; age is relative (9m ago).
  • Expanded card: YOUR REQUEST (real first user message + See more) · SESSION (Ran … · ended … ago, device once) · LINKS (ticket→Linear, PR/repo→GitHub, branch→copy) · one Resume on <device>.
